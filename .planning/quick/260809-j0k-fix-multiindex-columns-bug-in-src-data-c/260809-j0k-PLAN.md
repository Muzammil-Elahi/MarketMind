This bug is cross-phase: fixing it at the chokepoint unblocks Phase 3 UAT and prevents the same failure from silently recurring in Phase 4.
Output: `src/data/cache.py` flattens any MultiIndex column shape returned by `yf.download()` before it is cached or returned. A new regression test in `tests/test_cache.py` proves the flattening behavior directly against a mocked MultiIndex-shaped `yf.download()` return value, closing the gap where every existing test mocks `yf.download()` with already-flat columns and would not have caught this bug class.

Root cause (already diagnosed, do not re-investigate): `yf.download(ticker, period=period, progress=False)` in `_fetch_live()` returns a DataFrame with MultiIndex columns (e.g. `[('Close','AAPL'), ('High','AAPL'), ...]`) even for a single ticker, on the currently installed yfinance version. Downstream, `src/features/technical.py`'s `compute_sma`/`compute_rsi` call `ta.sma(df["Close"], length=window)` / `ta.rsi(df["Close"], length=window)`. With MultiIndex columns, `df["Close"]` returns a 1-column DataFrame instead of a `Series`, and `pandas_ta_classic` silently emits all-NaN output for a DataFrame input. `assemble_feature_frame(df).dropna()` in `src/pages/_universe_loader.py` (`fetch_scorable_row`) then drops every row, so every ticker reports `insufficient_data` (`MIN_HISTORY_ROWS = 20` in `src/recommendation/universe.py` is never met).
</context>
