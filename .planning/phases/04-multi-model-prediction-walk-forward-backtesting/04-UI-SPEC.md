# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Per 04-CONTEXT.md's Phase Boundary, this phase does not introduce a new page — it **extends the existing `src/pages/search.py` drill-in surface** (per 04-RESEARCH.md's Architectural Responsibility Map) with: a model dropdown (D-01/D-02), a forecast-horizon preset selector (D-03), an explicit "Generate Forecast" action (D-04), a forecast chart with a shaded confidence-interval band (PRED-03), a backtested-accuracy metrics table for the selected model (D-05), and a "Compare all models" action that shows a modal + persistent yellow warning banner + completion toast (D-06). The historical price chart (PRED-01, already shipped in Phase 3) is unchanged and always renders first. Explicitly NOT this phase's UI: LLM reranking/annotation surfaces (Phase 5), watchlist actions (Phase 6, WATCH-01/02), any new top-level page or nav entry (this is an in-page extension only).

## Spacing Scale

Declared values (must be multiples of 4), inherited unchanged from Phase 1/2/3:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. the toast's `check_circle` icon), inline badge padding |
| sm | 8px | Compact spacing between a backtest metric's label and its value within a metrics card |
| md | 16px | Default spacing between form fields / stacked elements; the horizontal gutter between the model dropdown, horizon selector, and Generate Forecast button; the gutter between the 3 `st.columns` in the "Compare all models" side-by-side view |
| lg | 24px | Card padding for the backtest metrics table container and each "Compare all models" per-model metrics card |
| xl | 32px | Gap between the forecast chart section and the backtest metrics section below it |
| 2xl | 48px | Vertical margin above the page heading / below the disclaimer banner — unchanged, same page |
| 3xl | 64px | Not used this phase (reserved, inherited) |

Exceptions (inherited, applies again here): icon-only controls use a 44px minimum touch target regardless of visual icon size, per accessibility floor. This is an addition to the spacing scale, not a replacement value.

New this phase: the model dropdown, horizon selector, and "Generate Forecast" button sit on one horizontal row via `st.columns` with `md` (16px) gutters when viewport width allows, wrapping to stacked rows at narrow widths per Streamlit's native responsive column behavior (same backstop pattern as Phase 3's card grid).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background — unchanged, same page as Phase 3 |
| Secondary (30%) | `#F0F2F6` | Backtest metrics table/card surface, each "Compare all models" per-model card surface, the disclaimer banner background — matches Streamlit's default `secondaryBackgroundColor`, inherited unchanged |
| Accent (10%) | `#0E7C7B` | See "Accent reserved for" below |
| Destructive | `#DC2626` | Reserved token, inherited — **not used this phase**; no destructive action exists on this surface (watchlist removal is Phase 6/WATCH-02) |
| Chart mark — historical (data-viz only) | `#334155` | The historical price line, unchanged from Phase 3's `build_price_history_figure` |
| Chart mark — forecast (data-viz only, new) | `#0EA5E9` | The forecast line (dashed) extending from the historical price line, per 04-RESEARCH.md Pattern 6 |
| CI band fill (data-viz only, new) | `rgba(14, 165, 233, 0.2)` | The shaded confidence-interval band around the forecast line (PRED-03), using Plotly's `fill='tonexty'` pattern between an invisible upper and lower bound trace |

Data-viz marks (historical line, forecast line, CI band fill) are exempt from the 60/30/10 chrome ratio, matching Phase 3's precedent — that ratio governs UI chrome (backgrounds/surfaces/CTAs), not chart data ink.

**Accent reserved for:** the "Generate Forecast" button (D-04) and the "Compare All Models" button (D-06) — the two primary actions this phase adds. **Not** used for: the model/horizon dropdown widgets themselves (native Streamlit control chrome, not a CTA), backtest metric values (rendered in default Heading/Body-role text color — a metric is informational, not a call-to-action), the forecast/CI chart marks (use the dedicated chart-mark colors above, never the accent color, so the eye is never drawn to a data point as if it were an interactive control), or the persistent yellow warning banner (uses Streamlit's native `st.warning` semantic styling, not a custom accent/hex override).

**Destructive reserved for:** unchanged from Phase 3 — **not triggered this phase**. Prophet-unavailable and insufficient-history messages both use `st.warning`/`st.error`'s default semantic styling for message text only (see Copywriting Contract), never a red-border widget highlight, since there is no persistent form field being invalidated.

| Compare-all-models modal heading (D-06) | "Comparing All Models" |

| Compare-all-models persistent yellow banner (D-06, same text as modal, shown while comparison runs) | "Comparing all models for this asset — this may take a moment." |
| Compare-all-models completion toast (D-06) | "Model comparison ready." (`icon=":material/check_circle:"`) |
| Compare-all-models section heading (post-completion, 3-column layout) | "Model Comparison" |
| Destructive confirmation | Not applicable in Phase 4 — no destructive actions exist in this phase's scope (watchlist add/remove is Phase 6, WATCH-01/02). The Destructive color token remains reserved, not newly used here. |

Notes:
- Per COMPLY-02 (non-directive language, formally audited in Phase 6 but binding on all copy written from this phase forward), none of the copy above uses directive verbs ("buy", "sell", "you should") or promises accuracy — "Sharpe Ratio (Simulated)" and the hypothetical-results caption exist specifically to keep backtest numbers framed as descriptive historical statistics, not guarantees, consistent with REQUIREMENTS.md's Out-of-Scope guardrail against "guaranteed/marketed accuracy percentages."
- The Compare-all-models modal and persistent banner intentionally share near-identical wording (per 04-CONTEXT.md's explicit instruction that both surfaces carry the same time-cost warning) — this is not copy duplication to fix, it is the specified behavior.
- "SMA Baseline", "XGBoost", "Prophet" model-option labels must exactly match the labels used in any "Compare All Models" 3-column output and in `src/prediction/`'s model-key constants at the string level the page displays, so a user can trace a compare-view card back to the dropdown option that produced it.

## UI Considerations

Applicable state considerations resolved: 12 covered, 4 backstop, 0 unresolved, 1 dismissed.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Forecast section (D-02, no model selected yet) | ✅ covered | Only the historical price chart + model/horizon controls render; no forecast chart, no backtest table, no placeholder copy below the controls — the empty state *is* the unselected controls themselves. |
| empty | Forecast section (model/horizon selected, "Generate Forecast" not yet clicked) | ✅ covered | Renders the "Select a model and horizon, then click Generate Forecast..." nudge copy above (Copywriting Contract). |
| loading | "Generate Forecast" click (SMA instant / XGBoost seconds / Prophet multi-second, per 04-RESEARCH.md Pitfall 1/6) | 🧪 backstop | Native `st.spinner` during the synchronous `generate_forecast()` call; Streamlit's synchronous execution model already blocks further widget interaction while running (also the DoS mitigation per Security Domain) — no custom skeleton designed this phase, verified at implementation/visual-QA time. |
| loading | "Compare All Models" click (up to 3 sequential trainings) | ✅ covered | Persistent yellow `st.warning` banner + `@st.dialog` modal both render with matching time-cost copy (D-06) for the duration of the sequential compare loop, followed by `st.toast` on completion (Pattern 5) — an explicit, designed loading treatment, not a backstop. |
| error | Forecast generation failure (engine/data error, not insufficient-history) | ✅ covered | Renders the "We couldn't generate a forecast right now..." error copy above in place of the forecast chart/backtest table. |
| error | Prophet import/runtime failure (04-RESEARCH.md Pattern 4/Pitfall 1) | ✅ covered | Renders the "Prophet isn't available right now..." fallback copy; Prophet option disabled/hidden in the dropdown while SMA/XGBoost remain fully usable — one bad model import never blocks the other two (Anti-Pattern in 04-RESEARCH.md). |
| partial | Insufficient prediction history (D-07/D-08, stricter than Phase 3's scoring threshold) | ✅ covered | Historical price chart still renders (non-blocking, same precedent as Phase 3's D-08); model dropdown and "Generate Forecast" button are disabled with the "Not enough price history..." explanatory message shown in place of the controls. |
| partial | Asset has enough history to score (Phase 3) but not enough to predict/backtest (Phase 4, D-07) | ✅ covered | Same resolution as the row above — this is the exact scenario D-07/D-08 describe; the two thresholds (Phase 3's `MIN_HISTORY_ROWS=20` vs. Phase 4's `MIN_PREDICTION_HISTORY_ROWS=750`) can legitimately disagree per-asset. |
| populated | Forecast chart with CI band (typical happy path, PRED-03) | ✅ covered | Renders via `build_forecast_figure` — historical line + dashed forecast line + shaded `tonexty` CI band, plus the "Shaded band shows an 80% confidence interval" caption (04-RESEARCH.md Pattern 6). |
| populated | Backtest metrics table, single selected model (D-05) | ✅ covered | Renders RMSE / Directional Accuracy / Sharpe Ratio (Simulated) in a bordered card below the forecast chart, mirroring Phase 3's Score Breakdown card treatment for visual consistency (D-05's explicit instruction). |
| populated | "Compare All Models" 3-column result (D-06) | ✅ covered | Each of the 3 models renders in its own `st.columns` card using the identical single-model metrics-table layout from the row above (04-RESEARCH.md Open Question 1's resolution: reuse, not a bespoke comparison component) — labeled by model name per the Copywriting Contract note on traceability. |
| overflow | Forecast/CI chart at narrow viewport width | 🧪 backstop | Plotly's `st.plotly_chart` is responsive by default (matches Phase 3's price-history chart precedent); no custom breakpoint logic designed this phase, verified visually at implementation time. |
| overflow | Extreme CI band width (e.g. very high-volatility crypto ticker at 90-day horizon producing a very wide band) | 🧪 backstop | No numeric clamping/truncation is designed this phase — Plotly's default y-axis autoscale handles arbitrarily wide bands; verified visually at implementation time that autoscale doesn't distort the historical-price portion of the same chart. |
| zero-one-many | "Compare All Models" result set | ➖ dismissed | Not applicable — the comparison is always exactly 3 models (SMA, XGBoost, Prophet) per D-06's fixed model set; there is no variable-count collection here the way there was for Phase 3's asset-class sections. The one real variability (Prophet unavailable) is handled by the dedicated "error" row above, not by a zero/one/many layout variant. |
| long-text | Prophet-unavailable / insufficient-history explanatory messages | 🧪 backstop | Both are short, fixed-shape template strings (see Copywriting Contract) with at most one variable substitution (ticker); standard `st.warning`/`st.error` text wrapping applies, no custom truncation logic needed — verified visually at implementation time. |
