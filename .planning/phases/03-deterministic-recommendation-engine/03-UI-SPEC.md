# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Per 03-CONTEXT.md's Phase Boundary, this phase has two UI surfaces: (1) a **Recommendations** page — a ranked, asset-class-grouped shortlist (top-N per class per D-05), each entry showing a composite score, a visible sub-factor breakdown (D-01/D-02), and a one-sentence templated explanation (D-06); and (2) a **Search** page — free-text ticker lookup (D-07) that renders the same asset drill-in view used when a user clicks through from a recommendation card, including the "insufficient data for scoring" fallback (D-08). This is also the **first phase with a recommendation/prediction view**, so per CLAUDE.md's compliance constraint and STATE.md's decision ("disclaimer UI component introduced as early as Phase 3, consolidated/audited in Phase 6"), both surfaces must render a persistent educational-use disclaimer — full non-directive-copy audit is Phase 6's job, not this phase's, but the component itself is built here. LLM reranking/annotation (Phase 5), forecast generation/confidence intervals/backtesting (Phase 4), and watchlist actions (Phase 6, WATCH-01/02) are explicitly out of scope for this contract — no "Add to Watchlist" button and no forecast controls appear on either surface this phase.

## Spacing Scale

Declared values (must be multiples of 4), inherited unchanged from Phase 1/2:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline badge padding (e.g. the "Insufficient data" badge) |
| sm | 8px | Compact spacing between a sub-factor's label and its bar in the breakdown mini-chart |
| md | 16px | Default spacing between form fields / stacked elements, Streamlit's native block gap |
| lg | 24px | Card padding for each recommendation card and the asset drill-in container |
| xl | 32px | Gap between asset-class sections on the Recommendations page (Stocks section to ETFs section, etc.) |
| 2xl | 48px | Vertical margin above the page heading / below the disclaimer banner |
| 3xl | 64px | Not used this phase (reserved, inherited from Phase 1) |

Exceptions (inherited, applies again here): icon-only controls (e.g. an expander's chevron toggle on the sub-factor breakdown) use a 44px minimum touch target regardless of visual icon size, per accessibility floor. This is an addition to the spacing scale, not a replacement value.

New this phase: recommendation cards within an asset-class section use `st.columns` with a fixed `md` (16px) horizontal gutter between cards — matches Streamlit's native column-gap default, no custom CSS gutter override needed.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | regular (400) | 1.5 |
| Body | 16px | regular (400) | 1.5 |
| Heading | 24px | semibold (600) | 1.2 |
| Display | 34px | semibold (600) | 1.2 |

Inherited unchanged from Phase 1/2 — exactly 2 weights (regular 400, semibold 600), no new sizes introduced.

- **Label** — sub-factor bar labels ("Profile Fit", "Momentum", "Volatility", "Quality", "Similarity"), asset-class section badges, disclaimer banner text, "Insufficient data for scoring" badge, search input helper/placeholder text.
- **Body** — the one-sentence templated explanation on each recommendation card, empty/error/partial-state copy, search-page instructional copy.
- **Heading** — page titles ("Recommendations", "Search"), asset-class section headers ("Stocks", "ETFs", "Crypto", "Gold", "Forex" — same labels as Phase 2's `ASSET_TYPE_OPTIONS`), the composite score number on each card and on the drill-in page (e.g. "82/100"), the ticker/asset name on a card and on the drill-in page.
- **Display** — not used this phase (reserved token, inherited; these are sub-pages under primary nav, not top-level wordmark screens).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background (both Recommendations and Search pages) |
| Secondary (30%) | `#F0F2F6` | Card surface behind each recommendation entry, the asset drill-in container, the disclaimer banner background — matches Streamlit's default `secondaryBackgroundColor`, no theme override required |
| Accent (10%) | `#0E7C7B` | See "Accent reserved for" below |
| Destructive | `#DC2626` | Reserved token, inherited from Phase 1/2 — **not used this phase**; no destructive action exists on either surface (watchlist removal is Phase 6/WATCH-02) |
| Chart mark (data-viz only) | `#334155` | The single bar series in the sub-factor breakdown mini-chart and the historical price line on the drill-in page. Data-viz marks are exempt from the 60/30/10 chrome ratio (that ratio governs UI chrome — backgrounds/surfaces/CTAs — not chart data ink); a neutral slate keeps chart ink visually distinct from the accent CTA color so the eye isn't drawn to a chart bar as if it were an interactive control. |

**Accent reserved for:** the "View Details" button on each recommendation card, the "Search" submit button on the Search page, and the active/selected item in `st.navigation` (inherited, unchanged from Phase 1/2). **Not** used for: composite score numbers (rendered in default Heading-role text color, not accent — a score is informational, not a call-to-action, and coloring it would dilute the accent budget's meaning), the sub-factor breakdown bars (use Chart mark color above, not accent), asset-class section badges, the disclaimer banner, or the "Insufficient data" badge.

**Destructive reserved for:** the invalid-ticker red-border pattern established in Phase 2's `login.py`/`profile.py` — **not triggered this phase**. The Search page's "ticker not found" state (D-08/D-07 error path) uses `st.error` with the Destructive-adjacent default Streamlit error styling for the message text only, not a red-border widget highlight, since there's no persistent form field to highlight (a single-shot search input, not a saved-record editor).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (recommendation card → drill-in) | "View Details" |
| Primary CTA (search) | "Search" |
| Page heading (Recommendations) | "Recommendations" |
| Page subheading (Recommendations) | "Your top-ranked assets across every asset class, scored against your investor profile." |
| Page heading (Search) | "Search" |
| Page subheading (Search) | "Look up any asset — stock, ETF, crypto, gold, or forex pair — even if it's not in your recommendations." |
| Search input label | "Ticker Symbol" |
| Search input placeholder | "e.g. AAPL, BTC-USD, GC=F, EURUSD=X" |
| Asset-class section headers | "Stocks", "ETFs", "Crypto", "Gold", "Forex" (identical labels to Phase 2's `ASSET_TYPE_OPTIONS`, for cross-page consistency) |
| Composite score label | "Score" — displayed as "{score}/100" (e.g. "82/100") |
| Sub-factor breakdown heading | "Score Breakdown" |
| Explanation sentence template (two contributing factors, D-06) | "Strong {factor_a} and {factor_b} match your {risk_tolerance} risk profile." |
| Explanation sentence template (one dominant factor) | "Strong {factor_a} matches your {risk_tolerance} risk profile." |
| Disclaimer banner (both pages, persistent, non-dismissible) | "For informational and educational purposes only — not financial advice. Scores and rankings are not personalized recommendations, and past performance does not predict future results." |
| Empty state (Recommendations, profile incomplete) | "Add a few details to your investor profile to personalize these rankings." (links to the Profile page; non-blocking — the list still renders using whatever profile data exists, per Phase 2's nullable-fields decision) |
| Empty state (Search, no query yet) | "Search for any asset to see its score, breakdown, and price history." |
| Error state (Recommendations, engine/data failure) | "We couldn't generate recommendations right now. Please try again shortly." |
| Error state (Search, ticker not found — D-07) | "We couldn't find \"{ticker}\" — check the symbol and try again." |
| Partial state (Search/drill-in, insufficient history — D-08) | Badge: "Insufficient data for scoring". Body copy: "We don't have enough price history for {ticker} yet to compute a score — here's what we have." (historical price chart still renders below this line, per D-08) |
| Destructive confirmation | Not applicable in Phase 3 — no destructive actions exist in this phase's scope (watchlist add/remove is Phase 6, WATCH-01/02). The Destructive color token above is reserved, not newly used here. |

Notes:
- Per COMPLY-02 (non-directive language, audited in Phase 6 but binding on all copy written from this phase forward), none of the copy above uses directive verbs ("buy", "sell", "you should") — "Score", "match your risk profile", and "top-ranked" are descriptive/informational framing, consistent with the Out-of-Scope guardrail against personalized advice language.
- The explanation-sentence templates above are the *only* two shapes REC-03 needs (one- or two-factor dominance) per D-06's directive that the sentence stay directly traceable to the visible sub-factor breakdown — the exact `{factor_a}`/`{factor_b}` label strings must be drawn from the same sub-factor label set as the "Sub-factor breakdown heading" row above (e.g. "Momentum", "Low Volatility", "Quality", "Profile Fit", "Similarity"), never independently-worded synonyms, so the sentence and the bars never drift out of sync.
- Per D-04 (fixed curated universe), an asset-class section may legitimately show fewer than the target top-N (e.g. only 2 gold instruments exist in the curated universe) — this is not an error state and needs no special copy; the section simply renders however many cards exist.

## UI Considerations

Applicable state considerations resolved: 11 covered, 4 backstop, 1 dismissed, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Recommendations list (profile incomplete — some/all scalar fields blank) | ✅ covered | Renders the "Add a few details to your investor profile..." nudge copy above alongside the still-rendered list (non-blocking, per Phase 2's nullable-fields precedent) — not a full-page empty state. |
| empty | Recommendations list (total engine/data failure — no asset in the universe scores) | ✅ covered | Renders the "We couldn't generate recommendations right now..." error-state copy above in place of the card grid. |
| empty | Search page (no query submitted yet) | ✅ covered | Renders the "Search for any asset to see its score..." empty-state copy above, above the (empty) search input. |
| loading | Recommendations list (scoring the full curated universe on page load) | 🧪 backstop | Streamlit's default rerun/spinner behavior applies while the engine scores the fixed universe against cached price/feature data; no custom skeleton is designed this phase — verified at implementation/visual-QA time, matching Phase 1/2's precedent for near-instant native-fetch loading states. |
| loading | Search/drill-in (ticker lookup + scoring on submit) | 🧪 backstop | Same reasoning as above — native Streamlit spinner during `fetch_ohlcv`/feature/scoring calls, not custom-designed. |
| error | Recommendations list (engine/data failure) | ✅ covered | Same resolution as the "empty" row above — the error and empty-collection states share identical copy/treatment since there is no meaningful visual distinction between "zero scoreable assets" and "the scoring pipeline failed" from the user's point of view. |
| error | Search (ticker not found / invalid symbol, D-07) | ✅ covered | Renders the "We couldn't find \"{ticker}\"..." error-state copy above, reusing the `st.error` treatment established in Phase 2's `profile.py`/`login.py`. |
| partial | Recommendations list (profile has some but not all scalar fields filled) | ✅ covered | Same resolution as the "empty/profile incomplete" row above — the nudge banner is not a binary on/off, it renders whenever any personalization-relevant profile field is blank, non-blocking either way. |
| partial | Search/drill-in (insufficient price history to score, D-08) | ✅ covered | Renders the "Insufficient data for scoring" badge + explanatory body copy above; historical price chart still renders below it per D-08 — the asset is never rejected outright. |
| partial | Recommendations list (curated universe has fewer than top-N assets in a given class, D-04) | ✅ covered | No special copy needed — the asset-class section renders however many cards exist (see Copywriting Contract notes); section headers are count-agnostic. |
| populated | Recommendations list (typical top-N-per-class happy path) | ✅ covered | Standard card-grid render, one asset-class section per class, `st.columns`-based grid within each section. |
| populated | Sub-factor breakdown mini-chart (typical 4-5 sub-factors per asset) | ✅ covered | Renders as a horizontal Plotly bar chart, one bar per sub-factor from D-01/D-02, using the Chart mark color declared above — same rendering function reused at compact size on cards and larger size on the drill-in page (not two independently-built components). |
| overflow | Recommendations list (asset-class section, card grid at narrow viewport width) | 🧪 backstop | `st.columns` wraps/stacks natively at narrower widths per Streamlit's default responsive behavior; no custom breakpoint logic designed this phase — verified visually at implementation time. |
| zero-one-many | Recommendations list (asset-class section with 0 / 1 / many cards, D-04) | ✅ covered | Section headers and card-grid layout are count-agnostic (see the "partial" row above for the 0-card sub-case) — no singular/plural copy variants needed. |
| long-text | Search input (unusually long or malformed ticker string) | 🧪 backstop | Standard `st.text_input` behavior — text scrolls/truncates within the fixed-width input without breaking layout; malformed/unfound tickers are caught by the D-07 error-state validation above regardless of input length, not by truncation logic. |
| long-text | Explanation sentence (one-sentence template, D-06) | ➖ dismissed | Not applicable — both explanation templates declared in the Copywriting Contract are short, fixed-shape sentences with only 2-3 short variable substitutions (factor names, risk tolerance level); there is no unbounded free-text input feeding this element, so overflow/wrapping risk does not apply the way it would to user-authored text. |
