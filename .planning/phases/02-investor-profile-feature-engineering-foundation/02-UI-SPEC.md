# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Per 02-CONTEXT.md's Phase Boundary, this phase has exactly one UI surface: the investor profile builder page (`src/pages/profile.py`) — a single always-editable form (D-12) covering risk tolerance, time horizon, preferred/excluded sectors, preferred asset types, capital, and a dynamic existing-holdings grid. The feature engineering module (`src/features/`) is pure-Python, zero-I/O infrastructure with no UI surface and is explicitly out of scope for this contract. Per ROADMAP.md's Phase 6 compliance note, no disclaimer banner is required on this page — it displays no predictions or recommendations, only profile input.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline field-hint padding |
| sm | 8px | Compact spacing between adjacent scalar fields (e.g. risk tolerance select stacked above time horizon select) |
| md | 16px | Default spacing between form fields within a section, Streamlit's native block gap |
| lg | 24px | Card/container padding around each logical section (scalar-fields card, holdings-grid card) |
| xl | 32px | Gap between the scalar-fields section and the holdings section — visually separates the two logical parts of the single form (D-12) |
| 2xl | 48px | Vertical margin above the page heading / below the save button |
| 3xl | 64px | Not used this phase (reserved, inherited from Phase 1) |

Exceptions (inherited from Phase 1, applies again here): icon-only controls — specifically the `st.data_editor` add-row (+) and remove-row affordances in the holdings grid — use a 44px minimum touch target regardless of visual icon size, per accessibility floor. This is an addition to the spacing scale, not a replacement value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | regular (400) | 1.5 |
| Body | 16px | regular (400) | 1.5 |
| Heading | 24px | semibold (600) | 1.2 |
| Display | 34px | semibold (600) | 1.2 |

- **Label** — form field labels (Risk Tolerance, Time Horizon, Preferred Sectors, Excluded Sectors, Preferred Asset Types, Capital), holdings grid column headers (Ticker, Quantity, Cost Basis), helper/caption text under fields.
- **Body** — page subheading/description copy, validation and error messages, empty-state caption above the holdings grid, save-confirmation message.
- **Heading** — page title ("Investor Profile"), the holdings section subheading ("Existing Holdings").
- **Display** — not used this phase (reserved token, inherited from Phase 1; the profile page is a sub-page under primary nav, not a top-level wordmark screen).

Exactly 2 weights declared (regular 400, semibold 600), inherited unchanged from Phase 1 — no bold/light variants introduced. Maps directly onto Streamlit's default `st.title`/`st.header`/`st.subheader`/body-text sizing.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background |
| Secondary (30%) | `#F0F2F6` | Card/container surface behind each form section (scalar-fields card, holdings-grid card) — matches Streamlit's default `secondaryBackgroundColor`, no theme override required |
| Accent (10%) | `#0E7C7B` | See "Accent reserved for" below |
| Destructive | `#DC2626` | Reserved token, inherited from Phase 1 — used in this phase for the invalid-ticker red-border highlight (D-08) only |

**Accent reserved for:** the "Save Profile" primary submit button, and the active/selected item in `st.navigation` (inherited, unchanged from Phase 1). Not used for borders, backgrounds, decorative elements, or the holdings grid's native add/remove-row chrome (that stays default Streamlit-widget styling, not app-recolored).

**Destructive reserved for:** the red-border highlight applied to the specific holdings-grid row/ticker cell flagged as unrecognized on submit (D-08) — reusing the exact `_highlight_empty_fields`-style scoped CSS-injection pattern already established in `src/pages/login.py` (keyed off the offending row's widget, cleared once corrected and resubmitted), not a new pattern. Not used for the `st.data_editor` native row-delete icon — that is unstyled Streamlit chrome, not an app-built destructive-confirmation flow (no delete-confirmation dialog exists or is needed this phase; see Copywriting Contract).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Save Profile" |
| Page heading | "Investor Profile" |
| Page subheading/description | "Tell us how you invest so we can tailor your recommendations. You can update this anytime." |
| Holdings section heading | "Existing Holdings" |
| Empty state (holdings grid, zero rows) | "No holdings added yet. Add a ticker below to get started." |
| Error state (invalid ticker on submit, D-08) | "We couldn't recognize \"{ticker}\" — check the symbol and try again." |
| Error state (profile save failure, e.g. Supabase write error) | "We couldn't save your profile. Please try again." |
| Save confirmation | "Profile saved." |
| Destructive confirmation | Not applicable in Phase 2 — holdings-row removal uses `st.data_editor`'s native delete-row affordance (select row, press delete/minus icon); no custom confirmation dialog is built or needed. The Destructive color token above is scoped to the invalid-ticker highlight only. A true delete-with-confirmation flow is deferred to Phase 6 (watchlist removal), per Phase 1's precedent. |

Notes:
- Per D-12 (single always-editable form for both create and edit), the page heading/subheading copy above is identical whether the user is completing their profile for the first time or editing an existing one — no separate "welcome, let's get started" vs. "edit your profile" copy variants are needed.
- Per D-13 (uncached reads), no stale-data banner copy is needed on this page (contrast with Phase 1's stale-price-cache banner) — the profile always reflects what's in Supabase at page-render time.
- Per RESEARCH.md Pattern 2 (all six new `profiles` columns nullable, no `NOT NULL`), scalar fields are not blocked from partial completion — there is no "required field" warning copy analogous to `login.py`'s `EMPTY_EMAIL_AND_PASSWORD_WARNING`. A user may save a partially-filled profile.

## UI Considerations

Applicable state considerations resolved: 10 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Scalar-fields form (first-time user, no profile row exists) | ✅ covered | Per D-12, the form renders with unselected/default values (empty selects, empty multiselects, capital defaulting to 0) rather than a separate "no profile yet" placeholder screen — the page heading/subheading copy above covers both first-visit and edit contexts identically. |
| empty | Holdings grid (zero rows) | ✅ covered | Renders the "No holdings added yet..." empty-state copy defined in the Copywriting Contract above, above an otherwise-empty `st.data_editor`. |
| loading | Scalar-fields form (profile fetch on page load, D-13 uncached) | 🧪 backstop | A fresh single-row Supabase query on every page load is expected to be near-instant; no custom skeleton/spinner is designed — Streamlit's default rerun behavior applies. Verified at implementation/visual-QA time, not by a wired assertion this phase. |
| loading | Holdings grid (holdings fetch on page load, D-13 uncached) | 🧪 backstop | Same reasoning as the scalar-fields loading row above — near-instant single-table fetch, native Streamlit rerun behavior, verified visually rather than specified further. |
| error | Scalar-fields form (profile save failure) | ✅ covered | Renders the "We couldn't save your profile..." error-state copy defined in the Copywriting Contract above. |
| error | Holdings grid (invalid ticker flagged on submit, D-08) | ✅ covered | Renders the "We couldn't recognize \"{ticker}\"..." error-state copy above, plus the red-border highlight described in the Color contract's Destructive row — reusing `login.py`'s `_highlight_empty_fields` CSS-injection pattern, scoped to the offending row. |
| populated | Holdings grid (typical few-to-several rows) | ✅ covered | `st.data_editor` renders as a standard editable table at any populated row count — no custom layout beyond the native widget is needed. |
| partial | Scalar-fields form (some fields filled, others left blank) | ✅ covered | Explicitly allowed, not blocked — per RESEARCH.md Pattern 2, all six new `profiles` columns are nullable with no `NOT NULL` constraint, so a partially-completed profile saves successfully with no required-field warning (contrast with `login.py`'s blocking pattern, which does not apply here). |
| partial | Holdings grid (cost-basis optional per row, D-07) | ✅ covered | `st.data_editor`'s native handling of an empty/blank numeric cell (nullable) covers a row with ticker+quantity filled but cost-basis left blank — no custom empty-cell styling needed. |
| overflow | Holdings grid (many rows) | ✅ covered | `st.data_editor` renders at a fixed default height showing a handful of visible rows with internal vertical scroll for the remainder — native Streamlit behavior, no custom overflow handling required. |
| zero-one-many | Holdings grid (0 / 1 / many rows) | ✅ covered | The "Existing Holdings" section heading and grid column headers are count-agnostic (no singular/plural copy variants needed) — a table view naturally scales from 0 to many rows without copy changes; the 0-row case is additionally covered by the empty-state row above. |
| long-text | Scalar-fields form (no free-text inputs) | ✅ covered | All scalar fields are `st.selectbox`/`st.multiselect`/`st.checkbox`/`st.number_input` — none accept free-text entry, so long-text overflow does not apply to this element's actual field set. |
| long-text | Holdings grid (ticker cell — unusually long or malformed entry) | 🧪 backstop | `st.data_editor`'s native text-cell behavior (fixed-width column, no custom wrapping) is expected to handle an oversized ticker string without breaking layout; not specified further, verified at implementation/visual-QA time. Malformed/invalid tickers are caught by the D-08 submit-time validation above regardless of display length. |
