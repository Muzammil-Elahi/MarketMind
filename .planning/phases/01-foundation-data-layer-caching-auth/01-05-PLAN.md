<scope_note>
**AUTH-02 edge probe — concurrent writes to the same profiles row (explicitly out of scope this phase):** Two sessions racing to UPDATE the same `profiles.last_login` value (e.g. two near-simultaneous `sign_in()` calls for the same user) is not covered by a dedicated concurrency test here. Rationale: a single-column UPDATE is atomic per Postgres's own MVCC guarantees — two near-simultaneous UPDATE statements against the same row cannot corrupt data or produce a torn write, so a dedicated race test would exercise Postgres's ACID guarantees rather than any Phase 1 application logic. This mirrors CONTEXT.md's Claude's-discretion pattern for implementation-level edge cases not locked by a D-XX decision (see D-06, D-09). The other AUTH-02 edge-probe item, trigger-idempotency (duplicate signup / duplicate INSERT), IS covered below in Task 2 and in Plan 02.
</scope_note>
