<objective>
Build the single yfinance chokepoint mandated by D-07/D-08/D-09: st.cache_data(ttl=3600) layered over a stdlib-SQLite disk cache layered over a tenacity-wrapped yf.download(), with an explicit stale-fallback path and no unhandled crash on failure. This is foundational data-layer infrastructure — later phases (3/4) are the first to actually render prices on a page, but the resilience mechanism must exist now so those phases inherit cold-start resilience rather than each reimplementing it (CONTEXT.md D-07).

Purpose: satisfies ROADMAP Phase 1 success criterion #3 (cache TTL + graceful degradation). REQUIREMENTS.md has no dedicated requirement ID for price caching — this plan is tagged AUTH-02 as the nearest fit (data-persistence infrastructure) since no CACHE-* ID exists in REQUIREMENTS.md; the actual driver is the ROADMAP goal text and CONTEXT.md D-07/D-08/D-09, both satisfied here regardless of ID mapping.

Output: src/data/cache.py, src/data/prices.py, tests/test_cache.py — all cache/backoff/degraded-state behavior proven with mocked yf.download() (no live network calls in the test suite, per RESEARCH.md Validation Architecture).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser session ↔ Streamlit process | st.session_state is the only per-user store; untrusted form input crosses here |
| Streamlit process ↔ Supabase Auth/Postgres | JWT-bearing HTTPS calls; get_user() is the server-side validation boundary |
| Streamlit process ↔ Yahoo/yfinance | Untrusted external network response (market data), no auth, potential malformed payload |
| Streamlit process ↔ local SQLite disk cache | Trusted local filesystem, but ticker input must still be parameterized before reaching SQL |
