# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Per ROADMAP.md/CONTEXT.md, Phase 1 ships only the login/signup screen (email+password + magic link) and the base multipage app shell/navigation with auth-gated pages hidden until logged in, landing on a minimal placeholder home page. No investor profile, recommendation, or prediction UI exists yet (Phase 2+). This contract is scoped accordingly.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn gate not applicable. Project stack is Streamlit + Python (per PROJECT.md/STACK.md), not React/Next.js/Vite; shadcn/Radix component registries do not apply to this runtime. |
| Preset | not applicable |
| Component library | Streamlit native widgets (`st.form`, `st.text_input`, `st.button`, `st.navigation`, `st.Page`, `st.error`/`st.warning`/`st.info`) — no third-party UI component framework |
| Icon library | Streamlit built-in Material Symbols (`:material/icon_name:` syntax in labels/buttons/`st.Page(icon=...)`) — zero-install, zero-cost, no new dependency, consistent with $0-budget constraint |
| Font | Streamlit default theme font (system sans-serif stack via `.streamlit/config.toml` default) — no custom font import; keeps zero added dependency/network fetch |

Source: `.planning/STACK.md` and `.planning/PROJECT.md` (Streamlit 1.59.x, $0 infra budget) — no design-system tooling was pre-populated by upstream artifacts, so these are researcher defaults appropriate to the confirmed stack.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline badge padding |
| sm | 8px | Compact spacing between form fields (email/password stack) |
| md | 16px | Default spacing between form sections, Streamlit's native block gap |
| lg | 24px | Card/container padding (login card, disclaimer/stale-cache banner) |
| xl | 32px | Gap between login form and page header/logo |
| 2xl | 48px | Vertical centering margin above/below the login card on desktop |
| 3xl | 64px | Not used this phase (reserved for future dashboard-scale layouts) |

Exceptions: icon-only nav/toggle controls (e.g., sidebar collapse, `st.Page` icons) use a 44px minimum touch target regardless of visual icon size, per accessibility floor — this is an addition to the spacing scale, not a replacement value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | regular (400) | 1.5 |
| Body | 16px | regular (400) | 1.5 |
| Heading | 24px | semibold (600) | 1.2 |
| Display | 34px | semibold (600) | 1.2 |

- **Label** — form field labels, `st.caption` helper text (e.g., "We'll never share your email"), disclaimer/stale-cache banner microcopy.
- **Body** — form error/success messages, placeholder home page body copy.
- **Heading** — section headers on the login page ("Log in" / "Create account" tab headers), placeholder home page heading.
- **Display** — app title/wordmark on the login screen ("MarketMind").

Exactly 2 weights declared (regular 400, semibold 600) — no bold/light variants introduced. This maps directly onto Streamlit's default `st.title`/`st.header`/`st.subheader`/body-text sizing without requiring custom font-weight CSS injection beyond what `.streamlit/config.toml`'s `baseFontSize` already controls.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background (login page, placeholder home page) |
| Secondary (30%) | `#F0F2F6` | Card/container surface behind the login form, sidebar/nav background — matches Streamlit's default `secondaryBackgroundColor` so no theme override is required |
| Accent (10%) | `#0E7C7B` | See "Accent reserved for" below |
| Destructive | `#DC2626` | Reserved token only — no destructive action exists in Phase 1's scope (no delete-account/delete-data flow); declared now so Phase 6 (watchlist removal) inherits a consistent token rather than inventing one later |

**Accent reserved for:** the primary "Log In" / "Create Account" / "Send Magic Link" submit buttons, the active/selected item in `st.navigation`, and inline hyperlinks (e.g., "Forgot your session? Log in again" link in the session-expired message). Not used for borders, backgrounds, or decorative elements — this is a deliberate default given no brand palette exists yet in PROJECT.md; if the user has an existing brand color, `gsd-ui-checker` or a later phase should update this token rather than the researcher guessing further.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (login) | "Log In" |
| Primary CTA (signup) | "Create Account" |
| Primary CTA (magic link) | "Send Magic Link" |
| Secondary action (logout) | "Log Out" |
| Empty state heading | "You're in" |
| Empty state body | "This is your home base for MarketMind. Your investor profile and recommendations are coming in a future update — check back soon." |
| Error state (invalid credentials) | "We couldn't verify that email and password. Double-check them and try again." |
| Error state (magic link send failure) | "We couldn't send your login link. Check your email address and try again." |
| Error state (session expired) | "Your session expired — please log in again." |
| Error state (stale/degraded price data — D-09) | "Showing saved data from {timestamp} — live prices are temporarily unavailable." |
| Destructive confirmation | Not applicable in Phase 1 — no destructive actions exist in this phase's scope (no account/profile deletion). Token reserved (`Destructive` color above) for Phase 6 watchlist removal. |

Notes:
- Per D-02 (email verification not required), there is no "verify your email" interstitial copy needed — signup copy should not imply a pending-verification step.
- Per COMPLY-01/02 (compliance, audited in Phase 6 but the disclaimer component is introduced early per STATE.md decisions), Phase 1 does not require a disclaimer banner since it has no recommendation/prediction views — this is confirmed out of scope for this phase's copy contract.

## UI Considerations

Applicable state considerations resolved: 9 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Login/signup form (unfilled) | ✅ covered | Native Streamlit form validation blocks submit on empty required fields; no custom empty-state copy needed beyond standard required-field behavior. |
| empty | Placeholder home page (no profile/recs yet) | ✅ covered | Renders the "You're in" empty-state heading/body defined in the Copywriting Contract above. |
| loading | Login/signup/magic-link form submit | 🧪 backstop | Submit button shows Streamlit's native in-flight spinner state (`st.spinner` or button-disabled-during-call) while `auth.sign_in_with_password`/`sign_up`/`sign_in_with_otp` is in flight — verified at implementation/visual-QA time, not by a wired assertion this phase. |
| loading | Nav shell before auth state resolves | ✅ covered | `st.navigation` is constructed synchronously off `st.session_state.get("logged_in")` on every rerun (Pattern 5, RESEARCH.md) — there is no async gap where an intermediate/unresolved nav state can render. |
| error | Login/signup form (invalid credentials) | ✅ covered | Renders the "We couldn't verify..." error-state copy defined in the Copywriting Contract above. |
| error | Magic-link form (send failure) | ✅ covered | Renders the "We couldn't send your login link..." error-state copy defined above. |
| error | Auth-gated page (session expired mid-session) | ✅ covered | Renders the "Your session expired..." error-state copy above, per `require_auth()` Pattern 1 (RESEARCH.md), then halts render (`st.stop()`). |
| error | Price-data fetch (stale/degraded — D-09) | ✅ covered | Renders the "Showing saved data from {timestamp}..." copy above; this is a Phase 1 data-layer concern surfaced in the UI per D-07/D-08/D-09, not a later-phase item. |
| populated | Placeholder home page (post-login happy path) | ✅ covered | Same as the empty-state resolution above — this phase has no data-bearing collection to populate, so "populated" and "empty" resolve to the identical placeholder content by design (no recommendations/profile exist until Phase 2+). |
| partial | Login/signup form (some fields filled, others missing) | 🧪 backstop | Native Streamlit `st.form`/`st.text_input` required-field validation surfaces per-field state; exact partial-fill visual treatment (e.g., which field is highlighted) is a Streamlit default, verified visually at implementation time rather than specified further here. |
| long-text | Email field (unusually long email address) | ✅ covered | Standard `st.text_input` behavior: text scrolls/truncates within the fixed-width input without breaking layout — no custom truncation logic needed. |
| long-text | Stale-cache banner timestamp/message | 🧪 backstop | Banner copy is a short fixed template (see Copywriting Contract) with only a timestamp variable substituted — length is bounded by design, verified not to wrap awkwardly at implementation/visual-QA time. |
