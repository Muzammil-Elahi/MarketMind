<assumption_delta_decision>
**Signal considered:** D-01 introduces two auth *methods* (email/password and magic link) for Phase 1. Does this mean `profiles.user_id` should model "one identity per auth method" instead of "one identity per person"?
**Decision: no-change.** Supabase's `auth.users` table is identity-first, not method-first: both email/password and magic-link sign-in resolve to the same `auth.users` row for a given email (there are not two separate user records for the two methods). `profiles.user_id` correctly stays a single foreign key to `auth.users(id)` with no per-method branching — the noun "user" already names the right thing.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser session ↔ Streamlit process | `st.session_state` is the only per-user store; untrusted form input crosses here |
| Streamlit process ↔ Supabase Auth/Postgres | JWT-bearing HTTPS calls; `get_user()` is the server-side validation boundary |
| Streamlit process ↔ Yahoo/yfinance | Untrusted external network response (market data), no auth, potential malformed payload |
| Streamlit process ↔ local SQLite disk cache | Trusted local filesystem, but ticker input must still be parameterized before reaching SQL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-01-01 | Information Disclosure | `src/data/supabase_client.py`, `src/auth/session.py` (`cache_resource` surface) | critical | mitigate | Token/identity confined to `st.session_state` only; the cached client stays stateless (Pattern 2); verified by the isolation test in Plan 05 |
| T-01-02 | Elevation of Privilege | `src/data/supabase_client.py`, `.streamlit/secrets.toml.example` | critical | mitigate | Client constructed with the anon/publishable key only (`SUPABASE_ANON_KEY`); no elevated-privilege credential is ever loaded into the deployed process |
| T-01-03 | Tampering | `src/data/cache.py` (SQLite queries) | high | mitigate | All price-cache queries use parameterized placeholders, never string-interpolated ticker input — enforced in Plan 03 |
| T-01-04 | Spoofing | `src/auth/session.py::require_auth()` | high | mitigate | `require_auth()` calls `auth.get_user(token)` (server-verified), never the client-trusted session read — enforced in Plan 02 |
| T-01-05 | Denial of Service | `src/data/cache.py` (yfinance fetch) | medium | mitigate | tenacity-wrapped fetch with exponential backoff; falls back to the stale SQLite row on any exception, never an unhandled crash — enforced in Plan 03 |
